為什麼我又回到 Claude Code：OpenClaw 用一個月後的退坑紀錄

發表於 2026-05-07 分類於 人工智慧
OpenClaw（前身 MoltBot）用了一個月，從新鮮感滿滿到徹底放棄。Claude 訂閱制鎖第三方應用是壓垮駱駝的最後一根稻草，但更根本的問題是黑箱執行、context 調整時間遠大於產出時間。這篇記錄我為什麼回到 Claude Code，以及這段路上踩過的坑。

離上次發文大概過了一個月，這段空窗不是因為懶——是因為我把整個工具鏈搬了一次家。

簡單講：我放棄了 OpenClaw，回去用 Claude Code。

這篇不是技術 tutorial，純粹是退坑心得。如果你正在 OpenClaw 上掙扎，或在猶豫要不要跳這個坑，希望我這一個月的血淚可以讓你少走一些彎路。

直接的導火線：Claude 把訂閱制鎖起來了

最表層的原因很簡單：Anthropic 不給第三方 agent 用 Claude 訂閱制了。

時間線其實很清楚——1 月 9 日就開始封 Max OAuth，2 月 19 日文件更新明確寫死，4 月 4 日 PT 12 點全面斷線。Claude Code 負責人 Boris Cherny 公開講過一句很白的話：「訂閱制本來就不是設計給 third-party 工具這種用法的。」言下之意——你們這群拿訂閱跑 agent 的，根本就在 abuse。

當時據估計有十幾萬個 OpenClaw instance 在跑，這數字嚇人，難怪 Anthropic 受不了要動手。受影響的 Pro/Max 訂戶有拿到一個月訂閱費 credit 當補償，算是有良心。

對 OpenClaw 這種「拿你 Claude 帳號去跑 agent」的工具來說，這基本上是斷頭。我本來還在想是不是改用 API key 模式繼續撐，但算了一下費用就放棄了——用 API 跑 agent，跑兩天大概就把一個月的 Pro 訂閱錢燒完。

如果只是要「讓 agent 多跑一點」，那 API 模式 ROI 完全不划算。所以與其在那邊掙扎，不如直接回去用 Claude Code，反正官方工具也夠用，甚至更好用。

但說實話，這只是個藉口。如果 OpenClaw 真的好用到我離不開，我可能還是會付 API 錢撐下去。問題是——它不夠好用。

黑箱：你只能等他跑完

回去用 Claude Code 之後我發現一件事：原來工具本來就應該是這樣的。

OpenClaw 最根本的問題是「黑箱」。你下了任務之後，他就自己跑，你只能等。他在思考什麼、要改哪些檔案、為什麼這樣決定，你完全看不到。等他跑完了，你看 diff 才知道他幹了什麼——然後通常會發現，他幹了一堆你不想要他幹的事情。

Claude Code 不一樣。他每一步都顯示在你眼前，你隨時可以打斷、可以糾正、可以說「等等，這個方向錯了」。這個差別聽起來很小，但在實際工作上是天和地的差距。

讓我用 mermaid 把這個對比畫出來：

            
            flowchart LR
    A[你下任務] --> B{選工具}
    B -->|Claude Code| C[每步顯示]
    C --> D[隨時打斷]
    D --> E[即時糾正方向]
    E --> F[結果可控]
    B -->|OpenClaw| G[黑箱啟動]
    G --> H[盯著進度條]
    H --> I[等他跑完]
    I --> J[看 diff 後悔]
    J --> K[從頭再來一次]

OpenClaw 的循環很容易陷入「跑 → 失敗 → 從頭再來」的迴圈，因為你沒辦法在跑的當下調整方向，每次都要等結果出來才知道。

你以為你在工作，其實你在調 context

這是另一個讓我棄坑的關鍵。

OpenClaw 跑得不好的時候，你第一反應是什麼？「我的 prompt 是不是寫得不夠清楚？」「context 是不是塞太多？」「是不是要改 system message？」「是不是要拆任務？」

然後你就開始一頓亂調。調了半天跑一次，跑完發現還是不對，再調再跑。

我有認真記錄過——一個下午，我大概有三個小時都在調 context、改任務描述、看他失敗、再改、再失敗。實際產出的程式碼，不到 20 行。

如果我直接用 Claude Code 自己寫，三小時能做的事情多到嚇人。

這就是 OpenClaw 最詭異的地方——你以為你在 leverage AI 提升效率，結果你變成 AI 的 prompt 助理，整天在伺候它的 context window。

但 OpenClaw 不是一無是處

講話要公道，OpenClaw 還是有他的優點。

最大的好處是 mobile。你可以在 Discord 上下指令，他就在遠端某個地方默默幫你跑。我有過幾次在咖啡廳、捷運上用手機派任務的經驗，那種感覺確實很爽——你只是在通勤，但你的 agent 已經幫你把一個小功能寫完了。

第二個好處是 iPad 終於變成「真．生產力工具」。以前 iPad 對我來說就是看影片、滑文章的玩具，有了 OpenClaw 之後它居然可以拿來推進實際工作。我朋友看到的時候問我：「你這個 iPad 真的有在做事嗎？」我說：「對，他在派 agent 寫 code」，朋友的表情我永遠記得。

但這些好處是有期限的。

新鮮感過後，真實成本浮上來

新鮮感大概可以撐兩到四週。

過了之後你就會發現一件事——你「能 mobile 工作」的時間，遠少於你「在家好好工作」的時間。算下來，這個工具大部分的使用情境，其實還是在桌前。而桌前用 OpenClaw vs 桌前用 Claude Code，根本沒得比。

更糟的是，因為 OpenClaw 比 Claude Code 慢、爛、難控制，所以「我桌前工作的效率」反而被它拖累。為了能在外面用 5% 的時間，犧牲掉 95% 在家的時間品質——這筆帳怎麼算都不划算。

越更新越爛：改名史本身就是一齣劇

這個我要好好吐槽一下。

很多人不知道，OpenClaw 其實改了三次名字。一開始叫 Clawdbot（致敬 Claude 的龍蝦圖案），1 月 27 日被 Anthropic 商標警告，改成 Moltbot；結果作者覺得 Moltbot「念起來不順」，三天後又改成 OpenClaw。光是改名歷史就告訴你這個專案的決策節奏有多浮躁。

我用的時候是 Moltbot 末期，那時候雖然有黑箱問題，但至少還算穩定。改成 OpenClaw 之後，就是直線式跳水。

第一個改名版本就先爛了一波，然後接下來的一個月，每次更新都讓我懷疑是不是版本反向走了。最誇張的是更新完常常要去跑 doctor 自我修復。對，就是那種「吃藥不會死，但吃完藥還是病」的感覺。

我大概更了三、四次之後就不想更了。但你不更他又開始警告版本太舊不支援——這種拉扯式的維護體驗最讓人崩潰。

一個工具讓你維護他的時間 > 他幫你做事的時間，那他就不算工具，是負擔。

這句話我要刻在牆上。

殘留戰場：股票管理與 News，現在都壞了

我雖然把工作搬回 Claude Code 已經一段時間，但 OpenClaw 上面其實還有幾個「不重要但有用」的 task 在跑：

  • 股票管理：每天自動拉行情、整理我關注的清單、寫進筆記
  • News：抓幾個技術社群的熱門文章、做每日摘要

這些東西不在工作流主軸上，所以我一開始沒有急著搬。但因為 OpenClaw 持續爛化，再加上 Claude 鎖了訂閱制——這些 task 現在基本上都是壞的。

我已經沒耐心去 debug 它了。再好的工具，當你不再信任它，你就不會花時間維護它。我寧願去找專門的工具或自己寫個小 script，反正只是抓行情、做摘要這種簡單事，半天就能寫完。

Hermes Agent：先觀望

最近社群開始討論一個叫 Hermes Agent 的新東西，是 Nous Research 在 2 月發布的。看起來想做的事情跟 OpenClaw 差不多——多平台、Discord/Telegram/Slack 都接、可以遠端派任務——但有兩個比較吸引我的點：persistent memory 和 skill creation。簡單講，他標榜會「越用越懂你」，解掉一個任務後會自己寫成 reusable skill，下次遇到類似問題不用從頭講起。

聽起來很美好。十週衝到 110k GitHub stars 也不是假的，社群熱度顯然在那。

但我還沒裝來試，老實說我有點被 OpenClaw 燙到了——任何標榜「全自動跑」「mobile 派任務」的 agent 工具，我現在第一個反應都是：

「他到底允不允許我介入？」
「壞了之後 debug 成本多高？」
「他的更新節奏會不會越改越爛？」
「persistent memory 累積錯誤的 context 會不會比沒記憶更糟？」

這些問題在我裝之前都沒辦法回答，所以我打算等個兩三個月，看社群反饋再決定。Hermes 跟 OpenClaw 一樣是用 LLM API 計費（沒了訂閱制這個問題後，反而更乾淨），所以即使試了不爽，也不會像當初 OpenClaw 那樣被 Anthropic 鎖到動彈不得。

如果有讀者已經試過 Hermes Agent，歡迎留言告訴我體驗如何。

給自己的小結

這一個月的退坑過程讓我整理出幾條原則：

  1. 能介入的工具 > 全自動的工具。 全自動聽起來很爽，但你失去控制的代價，往往遠大於你省下的時間。
  2. 新鮮感的保鮮期通常是兩到四週。 過了之後你才會看清楚這個工具的真實成本。前期感想都是虛的。
  3. 「跑」的時間不等於「產出」的時間。 跑半小時但結果不能用，等於零產出。但你心理上會覺得「我有在工作」，這是最危險的錯覺。
  4. 維護成本要算進總成本。 一個工具如果三天兩頭要 doctor、要重設 context，那它已經在跟你倒貼了。
  5. mobile 派任務的爽感是真的，但替代方案很多。 你不一定要靠 agent 工具才能 mobile 工作——一個能遠端 SSH 的開發機 + Claude Code，其實也能做很多事。

回到 Claude Code 之後我最大的感受是——終於可以好好寫程式了。每一步都看得見、可以隨時改方向、結果可預測。沒有 black box，沒有 doctor，沒有「我到底在跟誰打架」的精神內耗。

如果你正在 OpenClaw 上掙扎，或者你在猶豫要不要跳坑，希望這篇能幫你做決定。如果你已經跳了，歡迎來 Claude Code 取暖，這邊水溫剛好 😂
